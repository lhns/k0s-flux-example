# 0002 — First generators: an ArtifactGenerator, then flux-operator ResourceSets

- Status: Superseded by [0004](0004-one-kustomization-per-component-from-a-root-chart.md)
- Date: 2026-07-04
- Current answer: none of this is in use. Per-component Kustomizations were first written by hand
  from an ArtifactGenerator's ExternalArtifacts, then generated by flux-operator ResourceSets from a
  list of input lines. Both were replaced by the repo-root Helm chart. ExternalArtifacts returned
  later for a different reason ([0047](0047-externalartifacts-per-component.md)).

## Context

From the start every app had its own Flux Kustomization, so one broken app could not block the
others. The open question was how to produce them without hand-editing a list.

## Decision (as it was)

1. **ArtifactGenerator.** source-watcher packed each unit into an ExternalArtifact and a
   hand-written Kustomization consumed it. Dropped: per-unit Kustomizations from
   git paths keep the failure domains, and per-unit content hashing bought nothing at this scale.
   Fewest moving parts wins. source-watcher was uninstalled (2026-07-10).
2. **ResourceSet.** flux-operator generated one Kustomization per app, then per infra
   component, from one input line each.

## Why it was superseded

A ResourceSet still needs its input list kept in step with the directories. The Helm chart
derives the list from the tree itself (`.Files.Glob`), which removed the list and flux-operator
along with it.

## Consequences that outlived it

- The swap from one generator to the next established the procedure later formalised in
  [0012](0012-prune-off-around-risky-changes.md): disarm prune on the generated children, remove
  the old generator (the workloads are orphaned, not deleted), and let the new one adopt them
  under the same names.
